# Rentop KG: Telegram MVP для аренды

## Граница пилота

Это ручной пилот с сетью **ARCHA POINT**. У бота нет API-доступа к постаматам: менеджер Rentop вручную закладывает устройство, получает PIN/QR от ARCHA POINT и отправляет его клиенту через бота.

Документы и чеки принимает Telegram. В Supabase не хранятся фотографии паспорта, селфи или сам чек: бот пересылает их только в закрытый админ-чат Rentop. В базе остаются заказ, статусы и служебная отметка о том, что материалы были предоставлены.

## Клиентский сценарий

1. Клиент выбирает ноутбук, даты и способ получения на сайте.
2. Сервер создаёт минимальную заявку со статусом `pending_review` и возвращает одноразовый токен.
3. Сайт открывает бота по deep-link `https://t.me/<bot>?start=r_<token>`.
4. Бот показывает выбранные ноутбук, даты и способ получения; затем собирает имя, телефон, ID/паспорт, селфи и, при наличии, справку с места жительства или работы.
5. Бот пересылает материалы в закрытый админ-чат и создаёт карточку решения.
6. Менеджер одобряет или отклоняет заявку.
7. После одобрения менеджер вводит индивидуальный залог (можно `0`). Бот показывает клиенту сумму аренды, залог и выбор: MBANK или Синьбанк.
8. Клиент выбирает банк, получает реквизиты, оплачивает общую сумму и отправляет чек.
9. Менеджер подтверждает или отклоняет оплату.
10. Rentop готовит и вручную закладывает технику. Менеджер вводит PIN/QR, локацию и инструкцию в админ-боте.
11. Бот отправляет клиенту данные получения; заказ становится `awaiting_pickup`.
12. После выдачи менеджер отмечает `in_use`. При возврате: `return_requested` → `returned` → `completed`.

## Статусы заказа

| Статус | Значение | Кто меняет |
| --- | --- | --- |
| `pending_review` | Клиент прислал заявку и документы | бот |
| `rejected` | Заявка отклонена | менеджер |
| `awaiting_payment` | Документы одобрены, ожидается оплата | менеджер / бот |
| `payment_review` | Клиент прислал чек | бот |
| `awaiting_pickup` | Оплата подтверждена, техника готовится или уже загружена | менеджер |
| `in_use` | Клиент получил ноутбук | менеджер |
| `return_requested` | Согласован возврат | менеджер |
| `returned` | Ноутбук вернулся в Rentop | менеджер |
| `completed` | Заказ закрыт | менеджер |
| `cancelled`, `expired` | Заявка отменена или не завершена вовремя | менеджер / сервер |

## Доступы, которые подготовит владелец перед запуском

1. Новый токен бота из BotFather. Старый токен, который находился во фронтенде, нужно отозвать.
2. Числовой Telegram user ID каждого сотрудника, который может принимать решения.
3. Закрытый Telegram-чат для работы с заявками.
4. Production URL сервера (например, `https://api.rentop.com.kg`).
5. Service-role key Supabase — только для переменных окружения сервера.
6. Точные тексты реквизитов MBANK и Синьбанка — только в `server/.env`.

## Правила безопасности

- Никакие токены, service-role ключи, реквизиты или документы не размещаются в `index.html`, `js/` или Git.
- Админские действия доступны только Telegram user ID из `RENTOP_ADMIN_USER_IDS`.
- Клиентские deep-link токены должны быть одноразовыми и с ограниченным сроком действия.
- Перед запуском юрист проверяет оферту, политику конфиденциальности, срок хранения документов и порядок удаления данных.
